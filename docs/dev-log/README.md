# 开发日志规范

本目录用于记录“能耗哨兵”前端开发的真实过程，作为挑战杯/大创等竞赛的过程材料，也方便团队复盘和交接。

## 文件命名

- 按日期一个文件：`YYYY-MM-DD.md`
- 同一天多次开发可继续追加到当天文件
- `index.md` 维护时间线索引
- 截图统一放 `docs/screenshots/`，命名建议 `m<里程碑>-<页面>-<视口>.png`

## 记录节奏

- 每次开发结束写一篇
- M0–M8 每个里程碑至少一篇
- 里程碑验收当天必须附截图和验证命令
- 不要等全部做完再补写；日志的价值在于过程，而不是事后总结

## 质量要求

- 写清“做了什么、为什么这样做、遇到什么、怎么解决”
- 不要只写“完成页面”，要写页面解决了什么业务问题
- 数字、截图、命令结果可复核
- 记录取舍：为什么用 Element Plus、为什么 Mock 优先、为什么暂不全量按需引入
- 不写密钥、真实客户数据、个人敏感信息

## 快速创建

```bash
npm run log:new
```

脚本会在 `docs/dev-log/` 下生成当天骨架，已存在则不会覆盖。
